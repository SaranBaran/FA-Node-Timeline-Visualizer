Timeline difference report

Robert’s Combined Timeline view v27 (built 11.11.2026, database v13) compared with the FA Node Timeline Visualizer (Sarya, state of 17.11.2026). Written from the two code bases; no case details beyond counts are reproduced here.

1. In one sentence each

Combined Timeline v27 (Robert)

A full research instrument: the whole Miro wall plus the Mural context layer, people, dockets and absences, generated from a CSV database into one offline HTML file, with review and editing tools for the team.

Node Timeline Visualizer (Sarya)

A focused reader for one hand-built node sheet (one Miro board): events, their links and the family’s interventions, with a small, object-oriented React code base that is easy to change and test.

Worth raising: the two use different family-intervention marks. v27 draws a red ring; the Nov 2026 legend sheet (Legend_for_Miro-DY) says red hollow square. The Visualizer follows the sheet. Also, v27’s diamond means “investigation opened”, while in the Visualizer a diamond is any event, because the node sheet has no stage column.

6. What each one has that the other does not

Only in v27

  • The whole wall (500 legal cards) plus 1,315 context events
  • People, dockets, participation, absences and crime-scene elements as data
  • Per-event stage, court level and node shape, so the Miro symbols can be drawn
  • Date precision and the original date text
  • Sources, basis and status on the data; conflict checks
  • Location channels with crossing-minimised ordering
  • TR / EN, search, filters, greyscale, panels
  • Review mode with export; link editing
  • Runs as one file with the network blocked

Only in the Visualizer

  • Full-chain view, animated step by step
  • Lanes that can be regrouped (institution type, city, institution, case)
  • Family interventions always above their lane’s main line
  • Same-day parts separated from the main line
  • Rich hover card and a navigable side panel
  • Arrowheads that show direction
  • Legend generated from the drawing code
  • Small, modular, object-oriented code that can be tested piece by piece from the terminal

7. Trade-offs

  • Completeness vs readability. v27 shows everything at once, which makes it the better research tool and a dense first view. The Visualizer shows less but is easier to read for one board.
  • Generated vs hand-written code. v27’s view is one large generated file. That is easy to ship and safe offline, but hard to change by hand. The Visualizer is easy to change, but needs Node and a dev server, and has no build into a single offline file yet.
  • Data model. v27’s database is the richer and more careful model: dates with precision, separate people and dockets, provenance. The Visualizer’s sheet is simpler and faster to fill in by hand.
